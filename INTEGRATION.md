# Интеграция RAG в основной проект

Дата: 27 октября 2026.
Основной проект: `C:/Users/salfetka33/Desktop/msg-main`.

В проект перенесён новый RAG и объединён с последними исправлениями агента:
сохранены очереди действий, намерения перед отправкой команды, восстановление
после перезапуска, ограничения повторов и проверка эффекта. Панель использует
мой светлый интерфейс с боковым меню. Сравнительный проект остаётся источником
для чтения и для запуска не нужен.

Агент, инструмент `knowledge`, чат и раздел «База знаний» используют
`dome_agent.knowledge.KnowledgeService` и одинаковый механизм ответа.
Сервис лениво открывает SQLite только для чтения, сериализует запросы из
потоков и сообщает об отсутствии или повреждении базы. Ошибка базы не
разрушает защитный цикл агента.

Исправления:

* Текущие показания больше не считаются отвеченными справочными порогами.
  Ответ содержит `requires_live`, неполный вердикт, отсутствующие данные и
  отдельные `reference_facts`.
* Разные показания сами по себе не доказывают фальшивую тревогу. Для решения
  о текущем инциденте сохраняется требование независимой проверки.
* Варианты из каталога отказов остаются гипотезами; они не превращаются
  автоматически в рекомендации. Запрос списка файлов не предлагает запуск
  производства. Найденный текст не предоставляет права на управление.
* Подчёркивания в идентификаторах API (`node_id`, `list_files`) сохраняются.
* Пути базы по умолчанию определяются относительно пакета. Общие настройки
  базы применяются в агенте и панели. Лимит размера контекста соблюдается
  также для длинных вопросов.
* Добавлены недостающие исходные исторические журналы. Пересборка сохраняет
  37 узлов, 498 описаний параметров, 1300 карточек и семь эпизодов.
* Отсутствие корпуса или потеря журналов останавливает пересборку до её
  начала. SQLite создаётся во временном файле; ошибка сборки сохраняет
  предыдущую базу. Историческая схема параметров имеет отдельный резерв.
* Больше нет запуска через внешнюю папку бэкенда. Исправлены повторная
  загрузка журнала после ошибки и источник выбранного измерения CO₂ в чате.
* Убрана видимая маркировка версии. Обновлены инструкции запуска.
* Неподдерживаемая `stop_job` блокируется даже при старой разрешающей
  политике. Рабочая политика пользователя при установке сохраняется.
* Исправлен порядок закрытия ресурсов тестов в Windows.

Проверка:

* 259 Python-тестов: агент, политика, восстановление действий, клиент,
  локальный имитатор API, RAG, чат, HTTP-интеграция — пройдены.
* 22 проверки объяснений и состояний интерфейса — пройдены.
* 12 браузерных сценариев: мой интерфейс, основные страницы, RAG с цитатами,
  чат, отсутствие живой телеметрии, мобильный вид и отсутствие внешних
  запросов браузера — пройдены.
* Повторная сборка базы из включённого корпуса завершилась успешно.
* Дополнительные сценарии проверяют сохранение прежней базы при сбое,
  общий контекст RAG в контроллере и запрет сброса защиты с `force=True`.

Проверки использовали локальные данные и имитаторы. Соединение с настоящим
Куполом не устанавливалось. Проверка на действующем комплексе остаётся
отдельным этапом после получения рабочего адреса и свежей телеметрии.
Один DOCX содержит изображения без текстового слоя: нужен OCR. Оценки на
включённых наборах вопросов не являются гарантией безошибочности на новых
аварийных ситуациях.
