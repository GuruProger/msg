# Журнал решений и доказательная цепочка

Пункты 7.3 и 10.2-10.3 требуют восстановить использованные данные, вывод,
предложенное/выполненное действие и результат. JSONL программы - основа,
а не замена недостающим свидетельствам и решениям людей. Регламент не
предписывает схему полей ниже; это рабочий шаблон команды для выполнения нормы.

## 1. Шаблон записи

| Поле | Что фиксировать |
|---|---|
| Идентификатор | Игра, номер инцидента и решения, run_id |
| Обнаружение | Время с часовым поясом, игровой момент, кто обнаружил |
| Источники | Файл телеметрии/журнала, seq или диапазон, время самих измерений, узел/зона, качество и freshness |
| Независимая проверка | Какие источники независимы, разрешенная ручная проверка, противоречия и задержки |
| Вывод | Гипотезы, альтернативы, что подтверждено, что остается неизвестным |
| RAG / модель | Снимок корпуса, идентификаторы карточек/цитаты, verdict и ограничения, подтвержденная модель |
| Риски | Люди, оборудование, ресурсы, изделие и возможный каскад |
| Действие | Выполнить/отложить/отказаться, узел, команда и аргументы без секретов |
| Полномочие | Декларация, policy hash, разрешение интерфейса, подтверждение Оператора; исполнитель |
| Аварийный порядок | Факт останова, уведомленный ответственный, подтверждение получения; отдельное разрешение на возобновление |
| Отправка | seq action, точный запрос/ответ API, accepted/rejected/unknown |
| Физическая проверка | ref/seq verification, expected, observed, время и метод проверки |
| Итог | verified / no-effect / unknown; остаточные риски, следующий шаг, кому передано |

Для фактической игры использовать абсолютное ISO-время с часовым поясом.
Не заполнять неизвестные значения догадками. Ссылка на файл должна позволять
найти исходную запись; обобщение «проверили датчики» недостаточно.

## 2. Связь с текущими журналами

| Запись программы | Что дает | Чего может не хватать |
|---|---|---|
| `start` | run_id, версия, конфигурация, заявленное имя модели | Подтверждения организаторов, фактическая идентичность модели |
| `observation` | Сводка и метрики, время записи | Полный исходный кадр и время каждого измерения |
| `knowledge` | Вопрос, verdict, confidence, сокращенные источники | Полное извлечение, полный prompt, явная связь с каждым decision |
| `decision` | Вывод, план, команды/источник | `evidence` LLM может быть пустым; ручные подтверждения не всегда в этой записи |
| `action` / `action_blocked` | Запрос, ответ, причина, источник и ref | Физическая операция человека и основания допуска |
| `verification` | Ожидаемое/наблюдаемое, ok, ошибка, no-effect/unknown | Прямое наблюдение безопасности людей и готовности изделия |
| `action_reconcile` | Незавершенное намерение после рестарта | Подтверждение фактического эффекта до повторения |
| `message` | Направление, адресат, текст, отправка | Получение ответственным и полномочие разрешить возобновление |

`ref` связывает записи там, где поле действительно заполнено. Не соединять
разные команды по близкому времени, если явной связи нет; отметить ограничение
и дополнить его отдельной записью. UI читает ограниченный хвост и безопасное
подмножество state. Память чата панели очищается при перезапуске и не является
постоянным аудитом. Важное решение из нее переносится в этот журнал с источниками.

## 3. Учебный эпизод: подозрение на ложный CO2 и каскад

**Все события, значения и относительные времена ниже вымышлены для обучения.**
Это не журнал реального запуска и не свидетельство зачетной игры. Его нельзя
добавлять в оригинальные telemetry/agent JSONL.

| Момент | Данные и вывод | Действие и проверка |
|---|---|---|
| T+00:00 | Основной CO2 2500 ppm. Резерв 600 ppm с задержкой. Зона/качество третьего канала неизвестны. Реальная опасность не исключена | Инцидент открыт. Фиксируются исходные данные. При опасной обстановке - штатный порядок немедленно, без ожидания модели |
| T+00:10 | RAG описывает ложную тревогу в каталоге, но это не измерение и не доказательство отказа датчика | Блокировка сохраняется. Запрещена попытка «проверить» гипотезу отключением защиты. Запрос свежих независимых same-zone данных |
| T+00:30 | Дополнительный текущий надежный канал показывает высокий CO2 в той же зоне | Версия реального события усилилась. Оператор и ответственный получают контекст. Только разрешенные меры вентиляции/прекращения опасной работы |
| T+00:40 | API вентиляции вернул success | Это accepted, еще не verified. Проверить фактическое состояние вентиляции и динамику воздуха; записать expected/observed |
| T+01:00 | Вентиляция подтверждена, но нагрузка выросла и станок в UNDERVOLTAGE | Каскад «нагрузка -> питание -> производство». Не повторять resume; проверить питание и согласованные приоритеты нагрузок |
| T+02:00 | Причина локализована, состояние стабилизируется | Зафиксировать результат каждой меры и остаточные риски. Если был аварийный останов, возобновление ждет разрешения уполномоченного |
| T+после проверки | Безопасность подтверждена, полномочное разрешение записано | Проверить условия узла, выполнить допустимое возобновление, проверить реальный прогресс и отсутствие повторного hold |

Эпизод демонстрирует порядок п. 7.3: признак, независимые данные, безопасная
проверка гипотезы, оценка каскада, выбор исполнителя/полномочия, действие,
проверка и журнал. Числа не устанавливают нормативные пороги.

## 4. Сохранение и сдача

До игры: декларация, версии/хеши, policy, corpus manifest, исходное состояние,
подтверждение модели и разрешенных интерфейсов. Во время: полные исходные
JSONL, допустимая телеметрия и отдельные записи решений. После: итог состояния
систем, изделия и ресурсов, время окончания, последовательность событий и
перечень файлов с SHA-256.

Оригиналы сохранять неизменными. Корректировка - новая датированная запись
со ссылкой на исходную и автором. Секреты удалять из копий для передачи,
сохраняя происхождение и отдельно объясняя redaction; не подменять оригинал
«очищенной» версией без отметки. Фото/видео включать только с разрешенного
канала. Срок и форму сдачи уточнить у организаторов.
