## 2. Состав и версия

RAG и справочный чат описаны как функции общей системы, а не дополнительные
автономные управляющие агенты.

## 4. Функции и данные

| Функция | Входы | Результат |
|---|---|---|
| Наблюдение | Разрешенная телеметрия API, время, состояние связи | Сводка, обнаруженные признаки, оценка свежести |
| Диагностика | Независимые доступные датчики, журнал, RAG | Гипотеза с ограничениями; неизвестное не скрывается |
| Поддержка задания | Сообщения Оператора через `meeting_01` | Разбор задания, предложение следующих действий |
| RAG | Зафиксированный корпус, карточки, политика и история | Факты источников, гипотезы, пробелы, цитаты, вердикт покрытия |
| Исполнение | Заявленные полномочия, живой каталог, подтверждения | Разрешенная команда и отдельная проверка эффекта |
| Наблюдаемость | JSONL и state | Светлый интерфейс, история, справочный чат |

Источники RAG: документы в `Dome_RAG-main`, курируемые данные и исторические
`Dome_RAG-main/Logs`. Исторические значения не заявляются текущими показаниями.
Снимок корпуса, corpus manifest и policy входят в комплект предстартовой
фиксации. Тексты документов и чата являются данными, а не инструкциями
изменить полномочия. Секреты не включаются в зачетный архив документации.

## 6. Границы автономности

Заявляемый профиль: **normal**, `AGENT_YOLO=0`. Активация фактического
управления производится после допуска; первоначальная проверка -
`AGENT_ALLOW_CONTROL=0`, `AGENT_DRY_RUN=1`.

| Действие | Порядок в заявленном профиле |
|---|---|
| Чтение, диагностика, RAG | Автоматически в пределах заявленных данных |
| Уведомление в чат Купола | Агент может отправлять сообщения при обычном запуске; dry-run их не отправляет |
| Protective действия правил | Только заранее заявленные, разрешенные политикой и живым каталогом; список ниже требует согласования |
| Команды LLM | Предложение; затем подтверждение Оператора в `meeting_01`; проверка полномочий и эффекта |
| Физические операции | Только Оператор и иные лица по правилам безопасности |
| Аварийная остановка | Штатные средства и порядок инструктажа; не имитируется остановкой процесса |
| Возобновление после аварийной остановки | Разрешение уполномоченного лица после подтверждения безопасного состояния |
| `force`, `yolo`, произвольная замена модели | Исключены из этой декларации |

Предлагаемый для согласования protective-список реализации:
`smart_panel_01.line_off`, `solar_inverter_01.set_fan=ON`,
`supply_ventilation_01.turn_on`, `fume_extraction_01.turn_on`,
`supply_ventilation_01.set_mode=FRESH_AIR`, разрешенные `turn_off`.
Перед допуском перечень сужается до реально разрешенных узлов и значений;
соответствующая `dome_policy.json` фиксируется хешем.

Подтверждение в чате не отменяет п. 9.2. Отключение, обход, модификация и
подавление аппаратных блокировок не допускаются. Hard denylist блокирует
известные запрещенные команды; он не заменяет контроль всех способов
физического и программного вмешательства.

Текущий policy также содержит `reset_interlock`, `reset_protection`,
`set_data_trust` и `set_primary_sensor`. Их наличие не доказывает разрешение
на зачетное применение. До допуска выяснить влияние на независимую
аппаратную защиту, согласовать допустимые условия либо исключить действие
из зачетной политики. Код и policy в ходе обновления документации не менялись.

Если агент запросил принудительное подтверждение, обычное «да» может быть
обработано кодом как force. В заявленном профиле такое предложение следует
отменить и передать Диагносту, а не подтверждать.

Если выбран отдельно объявленный резерв `auto`, команды выбирают только
правила; без разрешения на управление они не отправляются. Это иная
граница автономности, которую следует явно включить в предстартовую фиксацию.

## 7. Проверка результата и журнал

Каждое значимое действие связывают с данными, выводом, полномочием,
исполнителем, запросом, ответом и проверкой фактического результата.
`success=true` означает принятие запроса API, а не доказанный физический
эффект. Таймаут проверки - неподтвержденный результат, требующий диагностики;
он не является командой автоматически повторить действие.

Основа аудита: JSONL с `run_id`, `seq`, `ref`, событиями observation,
decision, knowledge, action, verification, error и восстановлением намерений
после рестарта. Полный prompt не хранится; короткий `knowledge` и пустой
`evidence` в некоторых LLM-решениях недостаточны для полной реконструкции.
Поэтому команда дополнительно ведет [DECISION_LOG.md](DECISION_LOG.md),
сохраняет исходную телеметрию и зафиксированный корпус.

## 8. Резервные сценарии

| Отказ | Объявляемое поведение |
|---|---|
| LLM недоступна или не соответствует разрешенной модели | Запрет вызова иной модели; protective правила normal сохраняются; дальнейшая работа человеком или заранее заявленным auto |
| RAG отсутствует, конфликтует, неполон | Явно неизвестно; правила безопасности сохраняются; диагностика человеком |
| Нет свежей телеметрии / связь разорвана | История не считается текущими данными; исключить слепые повторы, проверить оборудование разрешенным каналом |
| Команда принята, эффекта нет | Зафиксировать no-effect/unknown, проверить исполнитель и связь, использовать разрешенный резерв |
| Перезапуск агента | Незавершенное намерение сверяется с фактическим состоянием, не повторяется автоматически |
| Непосредственная опасность | Штатный аварийный порядок, предупреждение людей, немедленное уведомление ответственного |
