# Кризисы: проверка признаков и планы действий

Основание: пп. 1.5, 7.3-7.4, 8.1-8.3, 9.1-9.4, 10.1-10.4 Регламента.
Это заявляемые планы реакции команды. Они не утверждают, что вся процедура
автоматизирована, и не раскрывают неизвестный сценарий организаторов.
Конкретные пороги берутся из подтвержденной конфигурации API/корпуса;
PDF-регламент не задает числовые пороги CO2, SOC или температуры.

## 1. Общий алгоритм по п. 7.3

1. **Зафиксировать:** время обнаружения, игровой момент, узел, сигнал,
   исходные значения, время самих измерений, качество и источник. Сохранить
   оригинал телеметрии и запись журнала.
2. **Проверить достоверность:** независимость источников, одинаковую зону,
   единицы, задержку, stale/offline, возможность общего отказа. Два канала
   одного зависимого источника не равны двум независимым подтверждениям.
3. **Сформировать гипотезы:** реальная опасность, отказ датчика/связи,
   сбой исполнителя, нарушение условий производства, каскад. RAG дает
   справочные варианты; их нужно сопоставить с текущими данными.
4. **Оценить последствия:** люди -> оборудование -> ресурсы -> изделие.
   При непосредственной угрозе не ждать завершения RAG/LLM: прекратить
   опасную операцию, предупредить людей, немедленно уведомить ответственного.
5. **Определить действие и исполнителя:** объявленные полномочия, живой
   каталог, policy, необходимость подтверждения человека. Не применять
   force, не менять защитные пороги, не подавлять аппаратную блокировку.
6. **Выполнить:** только разрешенный шаг. Физические операции - Оператором.
   Штатная аварийная остановка выполняется по инструктажу, а не неизвестной
   командой API или завершением процесса агента.
7. **Проверить результат:** принята ли команда, изменилось ли состояние
   исполнителя и устранена ли причина; проверить вторичные последствия.
   Success API не подтверждает физический результат, таймаут не разрешает
   бесконечные повторы.
8. **Зафиксировать решение:** данные, вывод, действие/отказ, полномочие,
   исполнитель, ответ и проверка эффекта, остаточные риски, передача человеку.
   Для аварийного останова отдельно записать разрешение на возобновление.

## 2. Состояния инцидента

| Состояние | Значение | Условие следующего шага |
|---|---|---|
| Обнаружен | Есть признак, причина неизвестна | Проверка свежих независимых данных |
| Проверяется | Рассматриваются реальные и ложные версии | Безопасная проверка гипотезы |
| Опасность подтверждена / не исключена | Есть достаточные признаки либо нет данных, позволяющих безопасно продолжать | Защитная реакция и эскалация по полномочиям |
| Датчик подозрителен | Найдены признаки недостоверного канала | Дополнительные данные; аппаратная защита сохраняется |
| Воздействие выполнено | Запрос принят или ручная операция сделана | Отдельная проверка фактического эффекта |
| Результат неизвестен | Нет подтверждения, связь/исполнитель неясны | Диагностика человеком, запрет слепого повторения |
| Стабилизирован | Подтвержден безопасный устойчивый результат | Отдельное решение о допустимости возобновления |
| Закрыт | Итог проверен, журнал заполнен, остаточные вопросы переданы | Новое событие открывается отдельным инцидентом |

Это рабочая модель журнала команды; отдельная автоматическая машина всех
этих состояний в текущем коде не реализована.

## 3. Планы по типам кризисов

| Ситуация | Что проверить независимо | Действие в пределах полномочий | Исполнитель и результат |
|---|---|---|---|
| Высокий CO2 / тревога воздуха | Свежесть, зона и состояние нескольких датчиков, доступная разрешенная ручная проверка, вентиляция | При реальной/неисключенной опасности прекратить опасную работу, уведомить; разрешенная вентиляция и иные штатные меры | Агент - только заявленные protective команды; Оператор/ответственный - физическая безопасность. Проверить состояние вентиляции и динамику воздуха |
| Предполагаемая ложная тревога | Задержки резервных каналов, независимость, скачок, несколько текущих same-zone показаний | Сохранить защиту, пометить гипотезу и передать контекст. Переключать источник только при разрешенной функции и подтверждении условий | Диагност и агент. Проверить новый источник и исходный канал; не сбрасывать аппаратную блокировку |
| Дым, пожар, CO, химическая опасность, радиация | Состояние каналов и время, признаки на месте разрешенным способом; не проверять ценой воздействия на человека | Непосредственная опасность: прекратить операцию, предупредить, уведомить, штатный аварийный порядок. Не ждать ответа модели | Оператор и ответственный за безопасность; агент уведомляет и выполняет разрешенные меры. Возобновление только по п. 9.4 |
| Конденсат / опасная влажность / охлаждение | Влажность, температура, точка росы, исправность датчиков, состояние оборудования | Приостановить небезопасную обработку; разрешенные режимы микроклимата. Не ускорять производство при неизвестной причине hold | Оператор/Диагност/агент. Проверить фактическую стабилизацию и отсутствие новых опасностей |
| Перегрев инвертора / низкий заряд / дефицит энергии | SOC, генерация, нагрузка, температура, токи и аварии линий, качество данных | Разрешенное охлаждение и отключение согласованных неприоритетных нагрузок; не подавлять защиту | Агент - по policy, Диагност - приоритеты. Проверить fan/линии, температуру, напряжение и влияние на станки/вытяжку |
| Остановка 3D-принтера / ЧПУ | state, hold_reason/level, interlocks, ошибка, питание, инструмент/стол; одного webhook недостаточно | Диагностировать причину; физические проверки Оператором; восстановление только после условий безопасности и разрешений | Агент предлагает/действует в своем профиле. Проверить реальное продолжение, прогресс и отсутствие повторного hold |
| Ошибка файла / незавершенный результат | Разрешенный список файлов, валидация, задание и фактическое изделие | Не запускать неизвестный файл; запросить допустимый вариант и проверить условия старта | Оператор/Диагност. Success старта не равен успешному изделию |
| API принял команду, эффекта нет | after-телеметрия, freshness, связь, исполнитель, питание, возможная задержка | Записать no-effect/unknown, соблюдать cooldown, не повторять до проверки; передать человеку | Агент и Диагност. Подтвердить физическое состояние независимым разрешенным способом |
| Потеря связи / stale-телеметрия | Время последнего полного кадра, роль, состояние сети, разрешенный локальный канал | Исторические значения пометить; не повторять незавершенную команду; действовать по резерву и опасности на месте | Диагност/Оператор; после восстановления сверить состояние и pending intent |
| Отказ RAG / модели / агента | Ошибка базы, вердикт, версия, доступность разрешенной модели, целостность state | Не менять модель на запрещенную. Protective правила normal сохраняются; заявленный auto или человек, без слепого воспроизведения действий | Инженер ИИ и Диагност. Проверить режим, очередь, аудит и границы полномочий |
| Каскад: энергия -> производство -> воздух | Временной порядок, взаимосвязь нагрузок, вентиляции, станков и связи | Сначала безопасность людей, затем локализация первичного отказа, затем ресурс/производство. Не лечить отдельный симптом бесконечным resume | Вся команда с одним текущим исполнителем каждого шага. Проверять каждый переход и вторичные последствия |

## 4. Ложная тревога: обязательные ограничения

Показания 2500 ppm и 600 ppm без сведений о времени, зоне и качестве не
доказывают ложность тревоги. Задержанный резерв не опровергает свежее опасное
значение. Согласованный кластер может поддержать гипотезу об отказе одного
канала, но не дает права отключить аппаратную защиту (п. 9.2).

Отдельно учитывать скрытую опасность: нормальное значение неисправного
датчика не доказывает безопасность. Каталог отказов и вывод модели не
являются независимыми измерениями. Уверенность RAG - оценка покрытия текста
источниками, а не вероятность отсутствия аварии.

## 5. Возобновление после аварийной остановки

До возобновления требуются: установление причины, подтверждение безопасного
состояния разрешенными средствами, разрешение уполномоченного лица и
запись этого решения с временем и источником. Повторно проверить людей,
вытяжку, питание, инструмент/стол и условия конкретного узла.

Текущий код проверяет условия ряда hold/resume, но не реализует отдельное
универсальное разрешение после аварийного останова. Поэтому обычный
автоматический resume или подтверждение предложения в чате нельзя считать
выполнением п. 9.4. Команда должна остановить автоматическое возобновление
в рамках согласованного эксплуатационного порядка и передать решение
уполномоченному лицу. Остановка процесса агента не является E-stop станка.

## 6. Карточка передачи человеку

Сообщить: **когда и где**, **что наблюдается**, **что достоверно / неизвестно**,
**какие независимые данные использованы**, **что уже выполнено**, **какой
эффект подтвержден**, **что запрещено повторять**, **какое решение требуется**.
Назначить принимающего, получить подтверждение получения и записать время.
Отправленное сообщение само по себе не доказывает, что ответственный его получил.
