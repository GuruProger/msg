# Купол — интерфейс, агент и база знаний

Это основной светлый интерфейс с боковым меню. Агент, просмотр журнала,
чат и новый RAG находятся в одном проекте. Папка со сравнительным проектом
для запуска больше не требуется.

## Запуск панели

Откройте `start_panel.cmd`. Адрес: http://127.0.0.1:8080/.
Загрузчик использует `.venv` или комплектный Python Codex и установленные
локальные зависимости. При первом запуске на другом компьютере он предложит
обычную установку зависимостей из `requirements.frontend.txt`.

Можно запустить вручную из корня проекта:

```powershell
python launch_frontend.py --port 8080
```

Панель сама не подключается к Куполу. Она читает `logs/agent_*.jsonl`
и `logs/agent_state.json`. Кнопка «Демонстрация» показывает синтетический
пример. Последнее записанное наблюдение всегда остаётся наблюдением из
журнала; ответ чата не превращает его в новое измерение.

## Что объединено

* `dome_agent` — последний вариант агента: очередь действий, защита от
  повторов после перезапуска, проверка фактического эффекта, контроль прав.
* `dome_rag` — карточки знаний, поиск, проверка покрытия вопроса, цитаты,
  известные пробелы и конфликты.
* `dome_agent/knowledge.py` — один сервис чтения RAG для агента, чата и поиска.
* `dome_dashboard` — API просмотра журналов и сохранённого состояния.
* `dome_web` — мой интерфейс, чат и настройки модели в памяти панели.

Обычный запрос в разделе «База знаний» работает без ключа модели. Чат тоже
показывает полный справочный ответ без модели. Для свободного пояснения можно
задать ключ, адрес и модель в настройках. Эти настройки живут до перезапуска;
секреты не возвращаются браузеру и не переписывают `.env` агента.

## Как читать ответ

`ANSWERABLE` означает, что источники покрывают вопрос. `PARTIAL` — данных
не хватает. `CONFLICT` — найдено противоречие. `NO_RELEVANT_EVIDENCE` —
подходящих подтверждений нет. Оценка уверенности относится к покрытию
вопроса документами и не является вероятностью исправности оборудования.

Каталог отказов описывает возможные причины, которые нужно проверить.
Описания не превращаются в команды. Расхождение двух показаний не признаёт
тревогу ложной и не разрешает сброс защит. Вопрос «что сейчас» требует
свежей телеметрии: справочные диапазоны показываются отдельно от измерений.
Для таких вопросов чат сохраняет детерминированный вердикт RAG.

Физические действия выполняет существующий агент через командную политику
и проверку эффекта. Чат панели формирует ответы и ничего не отправляет в
канал Купола. Управление агентом запускается отдельно через `main.py` после
настройки действующего адреса и прав в `.env`.

## Корпус и пересборка

База уже собрана: 1300 карточек, 37 узлов, 498 описаний параметров,
23 документа и семь исторических смен. Корпус лежит в `Dome_RAG-main/`,
путь в `dome_rag/corpus_manifest.json` относительный. `Logs` внутри корпуса
содержит историю; `logs` в корне проекта — журнал работающего агента.

```powershell
python -m dome_rag.kb stats
python -m dome_rag.kb ask "При каком CO2 срабатывает IL_CO2?"
python -m dome_rag.kb doctor
python -m dome_rag.kb build
```

Перед пересборкой остановите панель и агента, чтобы они закрыли базу.
Отсутствующие исходные документы или потерянные журналы останавливают
пересборку до перезаписи действующей базы. SQLite сначала собирается во
временный файл и заменяется только после успешной сборки. Схема ранее
наблюдавшихся параметров сохранена отдельно в `data/curated/node_schema.json`;
отсутствие примера телеметрии больше не стирает её. Это справочная схема,
актуальные возможности сервера проверяются по его API.

Настройки общие для агента и панели:

```dotenv
AGENT_KB_ENABLED=1
AGENT_KB_MAX_CARDS=6
AGENT_KB_MAX_CHARS=6000
# AGENT_KB_DIR=C:/path/to/dome_rag
# AGENT_KB_DB=C:/path/to/dome_rag/build/kb.sqlite
```

Старое имя `AGENT_KB` тоже поддерживается. Необязательные пути нужны только
для отдельной базы. Один из DOCX содержит изображения без текстового слоя:
его содержание требует OCR и отмечено как неполное.

## Проверка

```powershell
python -m unittest discover -s tests -p "test_*.py"
node --test tests/test_frontend_insights.cjs
```

Сетевые сценарии тестов используют локальный имитатор и подменённый клиент
модели. Настоящий Купол в проверках не участвует. Отчёт об этой интеграции
лежит в `INTEGRATION.md`.
